# Users Mock API

Небольшой REST API на **FastAPI**, предназначенный для автоматизированного тестирования API и проверки соответствия OpenAPI-контракту.

## Что реализовано

- **REST API пользователей**: список пользователей, получение пользователя по ID и создание нового пользователя.
- **Валидация данных**: проверка имени, email и возраста (18-65) с помощью Pydantic.
- **Контракт ошибок**: в OpenAPI описаны тела ответов `404` (`USER_NOT_FOUND`), `409` (`EMAIL_ALREADY_EXISTS`) и `422` (ошибки валидации, включая некорректный JSON). Ответ `400` не используется: на битый JSON приложение возвращает `422`, и это зафиксировано тестом.
- **Детерминированные тестовые данные**: данные хранятся в памяти и сбрасываются при создании нового экземпляра приложения. В начальных данных есть пользователь `alice@example.com`.
- **OpenAPI-спецификация**: генерируется из приложения и сохраняется в `openapi.json`.
- **Проверка актуальности спецификации**: тест сравнивает схему приложения с сохранённым файлом.
- **Генерация контрактных тестов**: Schemathesis генерирует запросы по OpenAPI и проверяет ответы на соответствие контракту.
- **Многошаговые сценарии**: тесты в `tests/test_user_scenarios.py` проверяют реальные пользовательские цепочки.

## Запуск

Установить зависимости:

```bash
uv sync --locked
```

Запустить тесты:

```bash
uv run --locked pytest -v
```

Пересобрать OpenAPI-спецификацию после изменений в приложении:

```bash
uv run python -c "import json; from app.main import app; print(json.dumps(app.openapi(), indent=2, ensure_ascii=False))" > openapi.json
```

## Тесты

| Файл                           | Что проверяет                                                 |
| ------------------------------ | ------------------------------------------------------------- |
| `tests/test_openapi_spec.py`   | `openapi.json` совпадает со схемой приложения                 |
| `tests/test_api_contract.py`   | Schemathesis генерирует запросы и проверяет ответы по OpenAPI |
| `tests/test_user_scenarios.py` | Многошаговые сценарии (см. ниже)                              |

Сценарии в `tests/test_user_scenarios.py`:

- создать пользователя → получить его по ID → увидеть его в списке;
- создать пользователя → повторить email → получить `409`, список не изменился;
- повтор email в другом регистре → `409`;
- email из начальных данных → `409`;
- граничный возраст 18 и 65 → `201`, возраст 17 и 66 → `422`;
- неверный email → `422`;
- битый JSON → `422` (а не `400`);
- несуществующий ID → `404` со структурированным телом.

## Примеры сгенерированных проверок

Примеры получены Schemathesis CLI на запущенном сервере.

Запустить сервер:

```bash
uv run uvicorn app.main:app --port 8000
```

В другом терминале запустить генерацию и сохранить запросы и ответы:

```bash
uv run schemathesis run http://127.0.0.1:8000/openapi.json \
  --max-examples 50 \
  --report vcr \
  --report-dir schemathesis-report
```

В `schemathesis-report/` сохраняются все отправленные запросы и полученные ответы. Те же файлы CI загружает как артефакт `test-results`.

Выбранные случаи из этого отчёта:

| Сценарий                       | Операция      | Отправленные данные | Статус | Выполненная проверка |
| ------------------------------ | ------------- | ------------------- | ------ | -------------------- |
| Валидное создание              | `POST /users` | ЗАПОЛНИТЬ из отчёта | 201    | ЗАПОЛНИТЬ            |
| Возраст на границе (18 или 65) | `POST /users` | ЗАПОЛНИТЬ из отчёта | 201    | ЗАПОЛНИТЬ            |
| Неверный email                 | `POST /users` | ЗАПОЛНИТЬ из отчёта | 422    | ЗАПОЛНИТЬ            |

## CI

GitHub Actions запускает при `push` и `pull_request`:

1. `pytest` (результаты в JUnit XML);
2. Schemathesis CLI против запущенного сервера (отчёт с запросами и ответами).

Используется кеширование зависимостей `uv`. Артефакт `test-results` (`pytest-results.xml`, `schemathesis-report/`, `uvicorn.log`) хранится 14 дней.
